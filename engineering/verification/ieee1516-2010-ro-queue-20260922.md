# Receive-Order Queue, Release And Restore

Date: 2026-09-22
Status: Implemented; Windows/Linux Go and Python campaigns passed.

This implements the linked RO work identified in the
[third conformance batch](ieee1516-2010-third-batch-20260922.md).
It is a bounded part of W1/W5, not completion of IEEE 1516-2010 conformance.

## Sources And Plan

The active 2010 text of the supplied IEEE 1516.1 redline supplies the oracle:
8.1.2 (original timestamps), 8.1.6 Table 3 (messages before grants),
8.1.7 (message eligibility and queues), 8.1.8 (subscription evaluation),
and 8.14-8.15 (asynchronous delivery). Licensed material remains outside Git.

The implementation separates message order from the presence of a timestamp.
An RO callback can retain a supplied timestamp without becoming TSO or
contributing to GALT/LITS. Reflection, interaction and removal are messages;
discovery, grants and other control callbacks are not put in the RO queue.

## Implementation

- A constrained, granted receiver with asynchronous delivery disabled holds RO
  messages. An unconstrained, advancing or asynchronously enabled receiver can
  receive them. Regulation alone does not restrict incoming RO.
- Object operations reserve the complete immediate/buffered recipient set
  under one time-evaluation lease. Typed, wire and regional paths share it.
- Resign-generated object removals use the same RO gate and retain the departed
  producer's identity. Ownership control callbacks remain immediate. Resign
  preparation acquires the evaluator before object and ownership locks; cleanup
  of superseded timed removals runs after releasing that evaluator lease.
- All five time-advance services release required RO before TAG. A blocked TAR
  can receive RO without receiving a premature grant.
- Asynchronous enable and constraint disable release eligible queued messages.
  Disabling asynchronous delivery does not recall accepted callbacks.
- Release reevaluates current ordinary, inherited and regional subscription
  interest. Attribute filtering does not mutate the original queue entry;
  a failed admission can retry against subsequently changed subscriptions.
  Removal still follows previous discovery after unsubscription.
- Pending RO has its own domain queue and does not affect TSO queue length,
  next-message targets, GALT or LITS. The MOM RO source counts this waiting
  queue, not every transport envelope or completed SDK invocation.
- Time snapshot version 4 stores pending RO, payload, tags, metadata and the
  original optional timestamp. Readers retain v1-v3 compatibility and reject
  RO fields labeled as an older version. Restore validates the state graph,
  handles previously deleted objects and departed senders, and rebinds federate
  identities without reinterpreting object or region handles as federates.

There are no Protobuf field, descriptor, RPC or configuration changes. The
legacy internal `TSOBufferedDelivery` name remains an alias for the extended
`MessageDelivery` descriptor. Persistence codecs remain outside the HLA layer.

## Review And Corrections

The plan/do/review/reflect cycle first reproduced premature RO delivery, then
implemented state transitions and persistence, and finally examined capacity,
lifecycle and integration failures.

Review identified two liveness defects in an all-at-once drain. An accepted
domain queue can exceed the bounded transport queue forever, and a failed
grant can remain pending without another public event to trigger evaluation.

Small drains still use one reservation. When transport capacity is insufficient,
the time service transfers a bounded prefix and keeps the unsent suffix. It
does not publish TAG before the required messages. Only explicit failed-work
hints are retried by one application-owned worker. The worker acquires
checkpoint and federation-generation admission, and cancellation joins it at
server shutdown. There is no background goroutine in the HLA time service.

Under transport overflow, asynchronous enable or constraint disable retains
the requested state and continues draining in the background. Other release
errors keep the prior mode retryable. A failed grant can still report an error
with an accepted pending request, as before; recovery no longer depends solely
on another federate operation. The worker resumes it without a duplicate TAR.

Existing regression assumptions were reviewed rather than skipped. RO callbacks
must retain supplied timestamps. Tests that intentionally receive RO while
constrained and idle explicitly enable asynchronous delivery. Restore tests
must distinguish the restored eligibility state from the existence of queued
messages. Payload, identity, ordering and exactly-once assertions remain.

## Remaining Scope

- Enabled delayed subscription evaluation also requires retaining candidates
  that were unsubscribed when a message was sent. Rechecking already-selected
  queued recipients does not implement that complete switch behavior.
- Regional filtering uses retained region identities and current bounds;
  preserving send-time region extents remains a separate review item.
- Default FOM preferred-order conversion, same-current-time TSO eligibility,
  unengaged advances and exact standardized time representations remain open.
- Domain waiting-queue length is not the complete end-to-end MOM queue measure.
- No throughput or latency experiment was conducted for this correctness change.
- The normative inventory, independent evidence and release attestation remain
  incomplete. Tests do not imply certification or full-standard coverage.

Existing unrelated working-tree changes are preserved. No commit, push or
history rewrite is part of this task.
