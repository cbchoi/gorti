## Immediate Findings

Completing the Java method map does **not** complete the RTI. The highest-impact
remaining requirements are exact Integer64 time throughout the RTI, persistent
restore through the selected Java interface, complete delayed subscription
evaluation, DDM region state/realization semantics, and complete MOM pending-message
accounting. The full obligation inventory remains missing. Conversely, implementing
IMMEDIATE callbacks is **not** a mandatory prerequisite when EVOKED is supported.

This is a selected actionable backlog, not an exhaustive inventory or a count of
remaining IEEE requirements. Priorities below are implementation/assessment order.

## Mandatory Backlog

### P0 / B1: Exact Standardized Time

**Required:** Both time representations and both Java factories, not a selectable
float-only product profile. S1 4.1.6, p.50; 12.4/Table 18/12.4.1-12.4.2, pp.338-340;
12.11.5.24.1-12.11.5.24.3, pp.359-360. S2 4.7.1, p.55 independently confirms both.

**Current gap:** `rti/internal/hla/core/time.go:7` uses `float64`;
`proto/rti/v1/time.proto:80` and subsequent time fields use `double`.
`javasdk/client/src/main/java/org/gorti/rti/AmbassadorServices.java:141` rejects
Integer64 creation and reports Float64 in federation listings. `types/TimeValues.java`
accepts only Float64; `client/src/main/resources/META-INF/services/hla.rti1516e.LogicalTimeFactory`
registers only `org.gorti.rti.types.Float64TimeFactory` (paths beneath `javasdk`).

**Next implementation/evidence:** Preserve the selected time type in federation
metadata, wire values, comparison/arithmetic, queues, grants, lookahead, queries,
timestamped object/DDM operations, retraction, MOM and save bundles. Add the Java
Integer64 values/factory and service discovery without editing the official API.
Exercise adjacent integers around `2^53`, `2^53+1`, `2^63-1`, ordering, overflow and
restart restore through actual Java callbacks. Both factories must be discoverable
by symbolic name and interface. Rejecting Integer64 is not a compliant exclusion.

**Do not reopen a historical defect:** Java `types/Float64TimeFactory.java:23` now
uses finite `Double.MAX_VALUE`, and `types/Float64Arithmetic.java` uses distinguishable
results for nonzero additions/subtractions. `types/TimeValuesTest.java` contains
focused endpoint/arithmetic tests. This does not establish backend-wide finite-final
semantics or exact Integer64 support; legacy internal infinity sentinels still need
an explicit, tested boundary policy.

### P1 / B3: Durable Restore Through The Standard Java Service

**Required:** S1 4.1.2, pp.43-44 requires persistent saved RTI state/messages surviving
execution destruction and restoration by replacement federates of matching types.
4.24-4.27, pp.73-76 specifies request admission, matching execution/FDD/census and
restored identity. Restoring federate application memory remains its responsibility;
the Java provider's RTI-side state is not application memory.

**Current gap:** `AmbassadorServices.java:59,541,641` keeps checkpoints only in memory,
fails a successful restore callback without the original checkpoint, and clears them
on membership reset. `SaveRestoreServices.java:75` sends only the standard label;
`rti/internal/hla/save_restore/manager.go:1085` searches the current generation unless
a product-specific saved generation is supplied. Thus there are two integration
gaps: source-save selection across execution generations and provider-local recovery.

**Next implementation/evidence:** Connect label-based standard restore to persistent,
validated save provenance, then persist or authoritatively reconstruct local object
knowledge, pending callbacks, time state, staged regions and retraction identity before
`federationRestored`. Test new JVMs, resign/rejoin, destruction/recreation, changed
handles, matching types, invalid census/FDD, failure atomicity and saved-message replay.
Use `rti/internal/application/server/restore_rebinding.go`, `save_restore/cross_generation.go`
and `internal/adapters/savebundle` as existing infrastructure, not a rewrite.

**Historical distinction:** `TestRestoreRestartFreshGenerationAllManagerState` in
`rti/internal/application/server/restore_restart_test.go` already covers server
restart with explicit `SavedFederationGeneration`; it is not standard Java
label-only/new-process acceptance evidence. Same-session Java restore and callback
epoch fixes are also implemented and should be preserved.

### P1 / B4: Region Templates, Realizations And Valid Empty Calls

**Required:** S1 9.1.1-9.1.3.1, pp.220-223; 9.3, p.230; 9.1.7, pp.228-229;
9.5-9.13, pp.232-247. Support services and Java pair collections must preserve these
semantics; see also 12.11.5.23, p.357. DDM is not optional for the full RTI scope.

**Current gaps beyond the concurrent method work:**

- `rti/internal/hla/ddm/manager.go:268` creates fully populated committed ranges.
  Its commit loop at `:338` checks existence/ownership but not whether every specified
  dimension was explicitly initialized. `operations.go:66` does not distinguish
  templates from specifications. Add that state and persist it; an incomplete first
  commit and use of an uncommitted template must produce the required region error.
- `ddm/state.go:236` materializes only explicitly committed ranges. Implement
  available-dimension-specific FDD defaults/exclusions when deriving realizations
  (S1 9.1.2(d), p.221; 9.1.3.1(f-g), p.222). An explicit zero-dimension region is
  not the default region or an empty region-designator set. Test defaulted dimensions,
  all-excluded realizations, and no overlap with even the default region in that case.
- `DdmServices.java:134,145,159` currently rejects valid empty registration/
  unassociation shapes and all association calls. Its grouped request handling is
  restricted. Concurrent DDM agents own additive/atomic pair support; verify their
  integrated result against the table below instead of retaining these exclusions.
- Conveyed regions require receiver-usable immutable realization copies during the
  callback, not unrestricted queries of mutable sender regions (9.1.7, p.229).
  Inspect `DdmServices.getDimensionHandleSet/getRangeBounds`, `ExchangeCallbacks.java`,
  `rti/internal/hla/object/queued_message.go` and region-query adapters together.

**Next evidence:** First-commit/template errors, empty collections, heterogeneous
attribute/region pairs, additive association, mixed-validity atomicity, ownership
loss/reacquisition, dimension defaults, conveyed-copy isolation and save/restore.
An intentional `RTIinternalError` on otherwise valid input avoids corruption but
does not implement the mandatory service.

### P1 / B5: Delayed Subscription Evaluation

**Required:** S1 8.1.8, p.191: the creation-time FDD switch controls when subscription
evaluation may occur; both settings require evaluation of current subscriptions at
delivery eligibility. The enabled setting is a conditional behavior the RTI must
support when selected, not permission to reject that configuration for full scope.

**Current gap:** Parser/model/exporter retain `delaySubscriptionEvaluation`, but
`object/interaction.go:87` and `object/update.go:627,999` select subscribers at send
time. `object/queued_message.go` rechecks retained candidates at release; it cannot
recover messages discarded because the receiver was initially unsubscribed.

**Next implementation/evidence:** Wire the immutable FDD switch into candidate
retention, queue filtering and persistence. Pair switch-on/off tests: send while
unsubscribed, subscribe before eligibility, then receive only where allowed; also
unsubscribe before eligibility, inherited subscriptions, RO/TSO, FQR, retraction
and restore. Determine/preserve the required DDM extent snapshots at the relevant
overlap boundary; current queued metadata retains region identities and queries
current bounds. Existing late-unsubscribe/FQR filtering is partial implementation,
not evidence that nothing has been done.

### P1 / B6: End-To-End MOM Pending-Message Metrics

**Required:** S1 8.1.1, p.182; 8.1.7, p.189; 11.6 Table 6, p.297; Annex G, p.583.
The normative MIM definitions are at
`rti/pkg/fom/mim/standard-mim.xml:326,340` (`HLAROlength`, `HLATSOlength`). Count
reflection/interaction/removal messages by received order until invocation, not
every control callback and not merely the time manager's waiting buffer.

**Current gap:** `rti/internal/application/server/mom_metrics_sources.go:85-94`
explicitly omits ready outbox/client stages, leaves `TimeMetrics.TSOQueued` unset,
and publishes only waiting RO length. `hla/time/metrics.go:36` counts that buffer.
`mom_ro_metrics_test.go::TestMOMROQueueCountsOnlyTimeWaitingMessages` tests this
bounded measure, not the complete standard metric. Java receipt reporting in
`AmbassadorServices.java:504` occurs after user callback return and is not an
invocation-start accounting mechanism.

**Next implementation/evidence:** Define one per-recipient message identity across
time queue, retry/outbox, transport and SDK queue; decrement on callback invocation
or a legitimate discard/retraction. Keep invocation start separate from completion
success/exception telemetry. Exercise disabled callbacks, a blocked callback body,
transfer between stages, retries, filtering, retraction, disconnect and restore;
assert no gaps/double counting. Existing observer/receipt infrastructure in
`internal/adapters/grpc/mom_receipts.go` is reusable but not a closure argument.

## Legitimate Scope Decisions

| Choice | Assessment and normative basis |
|---|---|
| Java as the only assessed standard API | Permitted by S1 13.2, p.390. Complete Java remains mandatory; C++/WSDL completion is not its prerequisite. Do not claim unassessed supplied bindings conform. |
| EVOKED only | Permitted by S1 4.1, pp.37-38; unsupported model is a Connect error, 4.2, pp.50-51. Java's two enum values (12.11.5.9, p.353) do not require both engines. Prove callback serialization, evoke-thread context and permitted reentry under 12.6, p.340, plus 10.41-10.44, pp.283-285. |
| Only one standardized time factory | Not permitted: B1. Custom time implementations may be supplied under 4.1.6, p.50 and 12.11.5.24.4, p.360; assess registration/selection when supplied. This does not require shipping every imaginable custom type, or make either standardized factory optional. |
| No application use of time, DDM, ownership, MOM or save/restore | A federation/federate usage choice, not an exemption for an RTI under 13.2. Conditional callbacks need tests when their conditions occur. |
| No cross-vendor saved-state portability | Permitted: S1 4.1.2, p.44 imposes no such requirement. This does not excuse same-implementation durable/new-federate restore. |
| No full OMT-authoring-tool claim | Legitimate separation of responsibility under S2 6.1, p.82. RTI FDD admission/combination, required MIM and relevant model semantics still apply (S1 4.1.4, pp.47-49; Annex F/G, pp.582-583). |
| A named OS/runtime and release | Declare and verify the actual configuration. This limits platform claims, not required service behavior. Parent owns release evidence and exact build capture. |
