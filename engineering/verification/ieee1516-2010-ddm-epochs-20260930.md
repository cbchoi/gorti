# DDM Association Lifecycle, Callback Knowledge, and Typed Time

Date: 2026-09-30
Branch: `codex/ieee2010-feature-completion`
Status: implementation increment; not complete IEEE 1516-2010 conformance

## Scope

This increment addresses three connected areas. Their completion levels differ:

| Area | Implemented | Still open |
| --- | --- | --- |
| DDM associations | Known-class mapping; per-federate inactive associations; activation on ownership acquisition; cleanup on loss, local deletion, region deletion and resign; persistence and identity rebinding | Exhaustive normative coverage across all DDM and callback interactions |
| Rediscovery during delivery | Process-local object-knowledge epochs; cancellable ownership-assumption checks at queue admission and server stream dispatch | Mandatory terminal callback receipt, and invalidation after wire send or while callbacks wait inside an SDK |
| Integer64 time | Exact typed bounds, LBTS, shared grant algorithm, outgoing timestamp checks and additive wire-value codec | Full server state, queues, services, persistence and SDK migration; Integer64 federation creation remains rejected |

## Plan and Implementation

### DDM

IEEE 1516.1-2010 clause 9.1.3.2 distinguishes association from ownership.
A federate may establish an inactive association before obtaining the attribute.
The old unconditional ownership prerequisite prevented that lifecycle.

`hla/object.PrepareKnownRegionAssociation` now pins object knowledge and ownership
while mapping recipient-known attribute handles to registered-class coordinates.
`hla/ddm` stores inactive associations by object, federate and attribute. Ownership
changes activate the new owner's associations and remove the prior owner's
associations. Local deletion removes only the caller's inactive entries. Region
deletion removes inactive uses; active uses still prevent deletion. Resign and
object deletion clean up the relevant entries.

Rate-admission rollback retains concurrent ownership and cleanup effects in a
shadow state. It must undo only the failed association request, not a successful
ownership transition that occurred while callback capacity was being checked.

The save adapter writes additive `DDMManagerState.inactive_associations` entries.
Older snapshots without that field restore an empty inactive set. Restore graph
validation checks membership, object/attribute existence, remembered class,
attribute visibility by name, region ownership and dimensions, duplicate entries,
and the distinction between active and inactive ownership. Federate rebinding
updates the associator as well as each region's creator. Preparation does not
publish partially restored state.

### Callback Knowledge

An object handle and even a known class can be reused after local deletion and
rediscovery. Matching those values alone cannot distinguish the old knowledge
lifetime from the new one. `hla/object.KnowledgeEpoch` therefore captures an
identity that is invalidated when knowledge is forgotten or its state is retired.
Attribute projection and epoch capture occur under the same object lock.

The delivery envelope keeps that identity through queue admission and batching.
Production ownership-assumption callbacks are explicitly cancellable advice.
An obsolete assumption is suppressed at server dispatch without terminating the
stream or suppressing subsequent discovery. Batched output rechecks after a
preceding chunk may have blocked. Other errors remain errors, not silent drops.

Terminal acquisition, unavailable and divestiture notifications are not treated
as cancellable advice. Their pending-operation lifetime must extend to a reliable
receipt boundary before applying the same policy. Existing MOM invocation receipts
are optional accounting and are not that semantic guarantee. The current epoch is
process-local; it does not protect a message already sent to an SDK.

### Integer64 Foundation

The Float64 manager and `DecideTypedGrant` execute the same generic decision
algorithm. Integer64 instantiations use integer comparisons and assignments.
`TimeBound` distinguishes an unbounded horizon from finite final time. Typed LBTS
and outgoing timestamp checks preserve adjacent values above `2^53`, reject mixed
representations and avoid wrapping at `MaxInt64`.

`common.LogicalTimeValue` adds a Float64/Integer64 oneof without changing any
existing RPC or field. The adapter checks the selected representation. Its raw
decoder rejects missing, duplicate or conflicting selectors and unknown fields.
The message decoder cannot recover overwritten selectors after ordinary protobuf
unmarshalling; future ingress must retain the appropriate raw validation boundary.
No existing service yet consumes this new message.

## Review and Corrections

- Independent tests reproduced three restore errors: missing object knowledge,
  reversed knowledge coordinates, and a child-only attribute whose numeric handle
  collides with an ancestor attribute. The new graph checks reject all three.
- Zero, unrelated and descendant known classes and forgotten deletion recipients
  are also rejected. A positive ancestor fixture verifies valid rebinding and
  later activation without losing another federate's inactive associations.
- Integer64 review covers 33,275 grant contexts, 2,097 additions against a
  `math/big.Int` oracle and 1,048 LBTS reductions. Another 12,960 contexts compare
  the typed Float64 entry point with the legacy path. A deliberately rounded
  external source overlay fails at `2^53+1`, confirming test sensitivity.
- Initial integration exposed old tests requiring `AttributeNotOwned` for a
  legitimate inactive association and a missing production composition hook.
  Actual Python/server tests exercise the composition, not only manager helpers.
- The real Python case exposed a separate SDK error: string-key updates searched
  all FOM classes, so an inherited attribute and a child-only attribute could
  resolve to the same numeric handle and overwrite one payload. String-key updates
  now query the caller's known class and resolve attributes only there. Numeric
  updates retain their direct path. Unknown names and duplicate string/numeric
  aliases fail before sending any update. Six new negative cases failed before
  this correction; the numeric-path control already passed.
- A final independent SDK review found no blocking issue. Two additional cases
  cover successful server lookup when the local class or attribute cache misses.

The string convenience path adds one known-class query per update, with attribute
lookup RPCs only on local cache misses. This favors correct rediscovery/restore
behavior over an unversioned object-class cache. Performance has not been measured
for that path in this increment; handle-keyed updates do not add those RPCs.

## Reflection

Manager-level tests did not detect a missing composition hook or Python's
cross-class name resolution. Real federate tests with deliberately colliding
handles were necessary to expose both. Keep these cases in subsequent campaigns.
Likewise, exact arithmetic alone cannot qualify a Float64 server as Integer64:
the full migration below remains a distinct acceptance requirement. Separate
region-template/specification realization semantics also remain outside this
DDM association increment.

## Remaining Integer64 Migration

The dependency audit found 79 non-test Go files using `LogicalTime` and 37 scalar
time fields across nine protocol files. These counts are lower-bound inventories,
not completed migration counts. Wall-clock durations and update rates are not
logical time and must not be converted.

1. Replace authoritative Float64 time state and ports with representation-aware
   values: regulation activation, lookahead reduction, all advance modes, GALT,
   LITS, TSO ordering, retraction and scheduled save. Do not add a competing integer
   side map beside Float64 state.
2. Carry exact values through OM/DDM services, callbacks, MOM/admin and all wire
   time fields. Require positive factory/capability agreement for participating
   SDKs; never place a rounded integer in a legacy double field.
3. Version snapshots and journals, preserve historical Float64 readers, and
   migrate SDK local checkpoints and retraction caches. Validate the manifest's
   selected representation before restore publication.
4. Exercise real mixed-language federations at adjacent times above `2^53` and
   near final time, including save/restart/restore, queues, callbacks and replay.
   Only then enable Integer64 federation admission.

The shared arithmetic and codec tests are useful prerequisites, not evidence of
full-server Integer64 support or full RTI conformance.
