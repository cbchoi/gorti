# Live FOM, Checkpoint, Rate, and Callback Implementation

This checkpoint follows the earlier
[service implementation checkpoint](ieee1516-2010-service-completion-20260920.md).
It records executable behavior, not a claim of complete IEEE 1516-2010
conformance. Existing unrelated working-tree changes are preserved.

## Implemented Boundaries

| Area | Behavior |
|---|---|
| Live FOM | A joining federate can supply additional modules. Class, inherited member, and dimension bindings remain stable. Preparation, writer reservation, the JOIN journal record, publication, and membership admission share a failure boundary. |
| FOM persistence | Exact ordered XML and history-dependent handle assignments are stored together. Restoring XML alone is insufficient after staged extensions. JOIN journal records retain the additional modules and resulting revision/digest. |
| FOM clients | The server returns authoritative bindings. Go, Python, and C++ consume these instead of reconstructing positional handles. Existing members can refresh the view. |
| Timed save | Requests crossing the scheduled checkpoint preserve their original targets and modes. Safe TSO delivery precedes initiation; completion resumes the original requests. Tests cover positive and zero lookahead. |
| Restore | Within the same federation generation, participant names are matched to saved identities. Successful completion rebinds membership, restores saved join-module metadata, rotates callback epochs, discards stale queued callbacks, and resumes saved pending time requests. Preparation or participant failure leaves the identity unchanged; an unexpected post-commit adapter failure is not a rollback. |
| Update rates | Active subscriber demand selects publisher attribute-update advisories. Passive subscriptions still receive matching data but do not drive production demand. Regional demand follows actual object/attribute overlap and current ownership. |
| Rate queries | Named rates are obtained from the FOM; effective object-attribute rates use actual subscription demand. Missing/default numeric information returns an error, not an invented zero. A genuinely named zero rate remains distinguishable. |
| MOM | Subscription, object information/count, module, and synchronization sources use live service state. Reports follow subscriptions; historical object counts count distinct identities. Attribute-state changes validate actual objects and ownership. Periodic reporting publishes available measurements. |
| Object callbacks | Tags, sent/received order, transportation selection, producer identity, received regions, and retraction metadata carry their actual presence. Order changes modify domain state and survive snapshots. |
| SDK lifecycle | Callback stream failures and restore identity transitions are handled explicitly. Compatibility callback forms remain available; missing required standard C++ metadata is not fabricated. |
| Retraction IDs | Originating timestamped sends reserve nonzero IDs before fanout. Duplicate accepted/in-flight IDs are rejected, including after delivery, retraction, resignation and restore. Saved/current history is merged; unused nonmonotonic IDs remain valid. |

An update-rate designator is not a license for the RTI to drop timestamped
updates or delay grants. This implementation advises the producing federate;
the model still decides when to produce updates. Callback admission and retry
are tested independently from successful network delivery.

## Review Corrections

The implementation cycle used failing assertions, production integration,
review, and revised regression tests. Significant corrections included:

- Acquiring the live FOM writer reservation before appending a JOIN record,
  preventing a durable successful join followed by a stale model publication.
- Moving post-join MOM publication outside the federation's exclusive join
  lease and removing recursive membership-lease acquisition from providers.
- Keeping RTI-internal MOM publishers out of external federate advisory queues.
- Resuming time requests after both save completion and successful restoration
  of a checkpoint containing pending requests.
- Preserving buffered callback metadata through save bundles and reclassifying
  received order correctly after a failed asynchronous-delivery retry.
- Reserving deletion callbacks before removing an object, so outbox failure
  cannot produce a successful deletion with missing callbacks.
- Fencing SDK restore transitions, invalidating stale FOM refresh responses,
  and exposing transition failures instead of leaving a silently dead stream.
- Acquiring MOM background checkpoint admission before its periodic-reporting
  lock, avoiding an outbox/restore lock inversion.
- Holding the regional-demand projection guard through a DDM mutation and its
  advisory rollback, so a concurrent ownership notification cannot publish
  rejected demand.
- Using qualified class identities in Python FOM diagnostics and inherited
  lookups, including repeated local names in different hierarchy branches.
- Invalidating DDM dimension caches on import even when an extension later
  reuses the pre-restore FOM revision number.
- Validating saved declaration rate designators against the unpublished saved
  FOM candidate, allowing untouched checkpoints with different extensions to
  restore in either order.
- Preserving accepted retraction-ID history independently of pending time
  queues. A fresh restored client must not reuse an ID and accidentally cancel
  an unrelated saved message.

## Compatibility

All protocol changes are additive. The current descriptor/RPC golden and three
layered projections check earlier wire surfaces. These are wire
compatibility tests, not official binding/ABI conformance tests.

Declaration snapshots now write version 3 and retain version 1/2 readers.
Older complete bundles without a FOM image retain the existing current-digest
check where otherwise sufficient for restoration. New bundles include the
exact FOM binding image, participant module history and a complete retraction-ID
ledger. Production restore now requires that ledger: older bundle framing is
readable, but missing complete ID history rejects restoration before effects.
Missing historical measurements remain explicitly unavailable.

## Remaining Boundaries

- Cross-generation restore is rejected. This work does not establish arbitrary
  recreation/restart restoration or full normative save/restore conformance.
- Retractable deletion is explicitly unsupported before side effects. Legacy
  timestamped deletion still removes global object state immediately; complete
  deferred deletion/retraction requires a coordinated object-lifecycle design.
- Automatic-resign server configuration remains unimplemented pending an
  explicit caller-authorization design. Client forwarding is not reported as
  end-to-end support.
- The C++ `attributeOwnershipReleaseDenied` path reports an explicit unsupported
  error instead of silently succeeding. Complete ownership negotiation across
  every standard binding overload remains separate work.
- Go LocalLRC is disabled after restore because its validation mirror is not
  reconstructed. Ordinary methods use the confirmed path; explicit local-queue
  calls report this limitation. Applications must wait for the restore terminal
  callback before issuing new service calls.
- Python's standard-style `evokeCallback` remains an immediate-style adapter;
  strict HLA_EVOKED dispatch semantics are not established. C++ stream restart
  is explicit and does not promise replay or exactly-once recovery.
- MOM periodic reports include available measurements, not fabricated values
  for every MIM attribute. Complete service-invocation instrumentation and
  regional MOM-report routing remain separate work.
- Full normative texts, applicability review, official binding coverage, and
  independent conformance evidence are still required for a full-2010 claim.
- Snapshot codecs validate their individual structures, but this checkpoint
  does not establish a complete cross-manager semantic validator for arbitrary
  externally modified bundles.

No new performance ranking, release, commit, or remote push is part of this
checkpoint.
