# IEEE 1516-2010 Defect Corrections

Date: 2026-10-03.

This increment corrects the six defect families reproduced in the
[2026-10-02 completion check](ieee1516-2010-completion-check-20261002.md).
Four parallel workstreams implemented the fixes and reviewed the boundaries.
The historical completion check and its failed execution records are preserved.
These corrections do not establish whole-RTI conformance.

## Corrections

| Boundary | Corrected behavior | Implementation |
| --- | --- | --- |
| Disconnected creation | Reject before dispatch or local federation-input caching; connected creation remains available. | Python `standard.py` |
| Connected nonmember | Sync/save/restore expose `FederateNotExecutionMember`; later join and synchronization remain usable. | Python `standard.py` |
| Occupied federate name | Return `FederateNameAlreadyInUse`, distinct from an already-joined caller. Definite admission rejection does not poison a Python connection, and a unique-name retry succeeds. | Federation manager, gRPC error mapping, Python `connection.py` |
| Pending timestamped deletion | Accept updates below or equal to the pending deletion timestamp; reject later updates with `InvalidLogicalTime`. Preserve guards for committed deletion and unstamped updates. | Object service `update.go` |
| Equal-time delivery | For the same object and timestamp, deliver accepted reflections before removal, then grant. Other object/message slots and receive-order queues are not reprioritized. | Time service `deletion_ties.go`, `asyncdelivery.go` |
| FOM local names | Validate XML names, local qualification separators and reserved prefixes/markers. Accept legitimate standard-MIM declarations and valid Unicode controls. Reject invalid create/join modules without partially extending the FDD. | FOM parser `local_names.go` |
| FOM error boundary | Map the new `FOM-017` rejection to `InvalidArgument` with `ErrorReadingFDD` metadata. Python retains `FomValidationFailed` as its compatibility base class. | Composition, gRPC adapter, Python `errors.py` |

The join recovery exception list is intentionally narrow: occupied name,
already-member, save-in-progress and restore-in-progress. Lost responses,
cancellation and unqualified internal errors retain commit-unknown protection.
This is not a claim that every rejected join is now retryable on the same SDK
connection.

FOM name checks use exact standard-MIM declaration identities, not a blanket
permission for `HLA` names. This increment does not implement every FOM naming
category, module merge condition or standard error-cause precedence.

## Red, Do, Review, Recheck

The retained red tests drove the changes. Component tests reproduced the
duplicate-name and facade defects before their fixes. A fresh run of the old
server reproduced seven FOM naming/extension failures out of eight cases.

The first rebuilt server passed FM but exposed two follow-up problems: invalid
FOM names were rejected as raw `INTERNAL`, and equal-time removal preceded an
accepted reflection in both logical-time families. That intermediate run had
13 passes and nine failures. It is retained, not counted as final evidence.

The callback-order defect was reproduced directly in four Go cases. Review
confirmed that correcting one object's reflection/removal tie does not require
a universal ordering among all equal-timestamp messages. The FOM error review
checked the invalid-module condition and the official Java create interface's
`ErrorReadingFDD` exception, rather than matching error strings.

Two older facade tests assumed deferred disconnected creation. They now check
offline rejection without cache mutation, then connect and retain their original
time-selector, copied-FOM and create/join controls. They were not deleted,
skipped or deselected.

The broad Python campaign found ten additional stale offline expectations in
MIM input/retention and logical-time selector tests. They now connect before
testing normal input validation, explicitly verify offline rejection where
relevant, and retain cache, request and selected-model/time assertions. Their
focused rerun passed all 12 cases; the final broad rerun follows these edits.

An independent SDK review found a further recovery hazard: a trailerless
`INTERNAL` response whose text contained "federate already joined" became a
definite already-member exception. Four status variants reproduced this failure.
The legacy text classifier now requires the matching admission status before
producing a class trusted by join recovery. Explicit standard exception metadata
retains precedence. Internal/transport failures, cancellation and missing status
controls stay commit-unknown; a positive legacy `ALREADY_EXISTS` rejection still
allows a same-connection retry.

## Broad Regression

The configured Go retry ran `./rti/...`, `./tests/...` and `./examples/...` with
the official local FDD schema, schema-capable Python and a real DDM endpoint:
**3,258 top-level tests and 6,531 nested pass records**, no failed or skipped
tests. Nested records are not added to the top-level total.

The first configured attempt had two ten-second fixture readiness timeouts before
service assertions, with empty child-server output. All other top-level tests
passed. A complete fresh retry with package concurrency limited to two passed;
the two affected tests took 1.16 and 1.28 seconds. Startup load is a plausible,
unproven explanation. Both attempts are retained, so this is not represented as
an unrestricted-concurrency first-pass success.

Linux race regression covered HLA, delivery and gRPC: **1,459 top-level and 2,290
nested pass records**, no failures or race warnings. Two top-level live-DDM tests
and eight mixed-commit variants skipped because that race run had no endpoint;
they are not race-qualified live-DDM evidence. The configured non-race Go run
executes those controls. XSD packages were outside the race scope.

Java regression passed **540 invocations in 57 suites**, no failures, errors or
skips. This includes 66 live-endpoint invocations and six additional server-restart
or fresh-JVM invocations, all using the pinned final binary. Time endpoint tests
and exact occupied-name exception mapping passed. Six historical fixture exchanges
and 462 other unit/in-process/fixture invocations are not live-server tests.
No existing Java runtime test asserts the new invalid-name `ErrorReadingFDD`
mapping; Python live and Go boundary tests cover that correction instead.

Python HLA/SDK regression passed **2,068 cases**, no failures or errors, with one
existing optional C++ interoperability skip. The campaign selects HLA/SDK tests;
it is not the entire repository's reinforcement-learning/pyjevsim test suite.
Unrestricted collection attempts were blocked by unavailable optional dependencies
in the inspected environments and remain recorded. The first HLA/SDK run had
ten stale offline-contract failures; they were corrected as described above,
not hidden by deselection.

## Conformance Status

All six reproduced defect families pass their final targeted checks. The new
callback-order and FOM error-boundary checks also pass. IEEE 1516-2010 defines no
Python language binding; Python cases verify this product's service behavior,
not a standardized Python-binding certification.

The earlier source census still contains unlinked obligations, unresolved
applicability, callback/statechart branches and table/schema/API decomposition
work. Closing these concrete defects must not be treated as closing whole clauses
or replacing independent assessment. `coverage_complete` and `full_conformance`
remain false. The previous dated traceability notes describe the retained failing
checkpoint; this report supersedes their reproduced-defect status only for the
specific boundaries and executions above.
