# IEEE 1516-2010 Third Implementation Batch

Date: 2026-09-20; final review continued on 2026-09-21
Branch: `codex/ieee2010-feature-completion`
Status: bounded implementation batch completed; whole-RTI conformance remains open

This batch continues the [remaining work plan](../design/ieee1516-2010-feature-completion-plan.md)
and the [second-batch checkpoint](ieee1516-2010-batch2-20260920.md). It changes
actual service paths and SDK inputs. It does not close the full conformance
assessment: complete normative texts remain unavailable, and the end-to-end
time, delivery and strict-binding work described below is not finished.

## Changes

### R1: FDD Transport And Rate Fidelity

Transportation declarations now retain their names, supplied reliability and
optional descriptions, including unused declarations. Update-rate descriptions
distinguish absent from explicitly empty text. Exact decimal rates survive fresh
JSON decoding through an additive `ExactRate` field; old JSON remains readable.
Conflicting or malformed exact representations fail without partially assigning
the destination model.

The exporter no longer invents reliability declarations from transportation
references. A missing referenced declaration produces `ErrUnsupported`, without
partial output. Legacy reference-only inputs remain readable by the parser and
runtime. Existing source fixtures were not rewritten; success tests requiring
standard declarations explicitly supply the decoded MIM declarations.
Retaining a transportation declaration does not add support for a new transport.

The independent oracle checks authored source, exported XML and fresh JSON/model
reconstruction against the local official XSD. It includes seven schema-valid
semantic mutations and four schema-invalid mutations for each vector.

### R2: Explicit Selected MIM

Selected MIM input has its own role, separate from the ordinary FOM module list.
The repository retains its exact source and designator through current model
views, additive joins and save/restore. MOM reads the committed selection instead
of reporting a fixed designator. Omission preserves the historical embedded MIM
and FOM-only digest; explicit selection contributes a separately framed digest.

Additive fields are `CreateFederationRequest.mim_module` (8),
`FOMView.mim_module` (7), and `JoinFederationRequest.expected_mim_module` (7).
Explicit selection/expectation uses the V2 create/join request profile. Other
calls remain V1. Old servers reject V2 instead of silently ignoring the selected
MIM, and SDKs must not retry by removing it.

The join expectation is checked under exclusive lifecycle admission before FOM
extension or membership allocation. Checking only the returned view and then
resigning is insufficient: that cannot undo an already committed FOM extension.
Negative tests check that mismatches leave the roster and model unchanged.

The supported selection profile keeps the embedded MIM's ordered structure and
non-descriptive definitions. Formatting, comments and supported semantics text
may vary. This is a real but bounded selection profile, not unrestricted MIM
replacement or a normative judgment that all other MIMs are invalid.

### R3: Actual Outbox Diagnostics

The production delivery adapter now optionally counts admitted, channel-drained,
invalidated, scratch and queued envelopes. Send, reservation commit, timed flush,
close and restore use the same observation state. Its bounded storage retains
batch lengths, not callback payloads, transfer identities or terminal history.
The conservation identity is:

```text
admitted = channel_drained + observation_invalidated + scratch + queued
```

Normal constructors keep accounting disabled. Server composition enables it only
when DEBUG logging is enabled at startup. The resign hook retains an observation
before unbinding and logs its detached final snapshot with `scope=outbox-only`.
If a stream already removed that binding or concurrent cancellation has not yet
closed its observation, no final snapshot is fabricated.

These counts include control envelopes. Channel removal is not SDK enqueue,
callback invocation or producer ACK. Invalidation ends the observation epoch;
it does not prove cancellation of a callback already in another queue.
`HLAROlength` and `HLATSOlength` remain unavailable rather than being populated
with partial totals. Shared delivery identity and authenticated SDK progress
reports are still required for end-to-end accounting.

Disabled execution adds nil checks but no accounting locks, counters, allocations
or worker goroutines. Literal zero CPU overhead or a performance improvement is
not claimed. The experimental end-to-end ledger remains separate.

### R4: Resign Outcome Reporting

A successful resign formerly retired its MOM state before the RPC observer
reported the result. The new lifecycle outcome hook runs after roster removal
and before derived-state cleanup, under the exclusive operation lease. It reports
the actual result and actual retired handle, including restore rebinding.
The normal interceptor still observes calls rejected before that hook, and a
request-local marker prevents reporting a committed outcome twice.

Routing permits this specific terminal report for the retained MOM subject while
excluding the departed member as a recipient. Other service reports still require
a live subject. Observation errors do not change the resign result. The live
regression covers failed and successful calls, serial numbers, a self-subscribed
departing member, survivor delivery and stale-session rejection.

Independent review found that the ordinary fallback trusted a requested handle
after signed resignation was rejected. It could therefore attribute caller A's
rejected request to unrelated member B. The correction resolves the authenticated
caller for that fallback; unavailable or forged credentials produce no invented
subject. The completed lifecycle hook keeps its already validated identity and
does not reacquire its own exclusive lease. The rejected-request resolver also
reuses the checkpoint admission already held by the interceptor; reacquiring it
could block behind a pending checkpoint. Focused repetitions cover that boundary.

### R5-R7: SDK Work

Both modern C++ and the strict C++14 foundation now implement exact integer64
time/interval values and factories, including values above 2^53, checked
arithmetic, independent big-endian encoding and allocation-error conversion.
Review also fixed a timed-save string-to-double conversion that admitted the
wrong time type and rounded float64 timestamps. The backend remains float64;
typed operations reject integer64 rather than converting it. Strict service and
callback ABI work is separate from this local value implementation.

Python adds a separate `mim_module` keyword/value and retains successful selection
for later joins. Rejected create calls do not replace the facade's local state.
Federate-bound support lookups and save/restore status queries forward the joined
session capability. Legacy unsigned clients remain unsigned. Live tests verify
actual MOM attribution; deleting metadata forwarding in a mutation probe makes
the oracle fail.

The Go, Python and C++ selected-MIM paths use the coordinated V2 create/join
profile without downgrade. Unsupported time-kind selectors still fail before
creation. Factory availability alone is not backend time support.

Independent C++ review reproduced an inconsistent-response case: a successful
join response could omit or replace the selected MIM and overwrite the cached
expectation, causing a later join to downgrade or request the wrong selection.
This used a fault-injected server response, not a mismatch emitted by the current
Go server.
The join now checks its immutable request expectation before installing local
membership, caches or a callback stream. On mismatch, a returned nonzero handle
and session token permit a bounded, authenticated NO_ACTION cleanup attempt;
missing credentials never trigger unsigned cleanup. The error distinguishes
successful cleanup from uncertainty and does not claim to undo additional FOM
publication. Authoritative refresh after restore remains supported.

## Plan, Do, Review, Reflect

1. Plan: split model fidelity, selected MIM, actual delivery observation, MOM
   lifecycle, C++ time values and Python forwarding into separate ownership areas.
   Keep shared schema regeneration with one owner and preserve existing dirty work.
2. Do: reproduce lost/invented declarations, JSON precision loss, ignored MIM
   input, missing resign reports and absent runtime diagnostics with behavioral
   tests before their fixes. Run actual local services and independent XML checks.
3. Review: inspect changes across workstreams. Correct foreign `probe:xmlns`
   attribute acceptance in the selected-MIM validator; exact JSON null/base-slice
   merge cases; pre-mutation MIM expectation; rejected signed-resign attribution;
   a concurrent cancellation window that could log a non-final queue snapshot;
   and C++ selection-cache replacement after an inconsistent join response.
4. Reflect: retain failed-run evidence and add regressions. Do not turn adapter-only
   counts into MOM totals, factory support into backend time support, or a bounded
   MIM selection profile into a full conformance claim.
