## Restore and Callback Behavior

Local checkpoints copy callback-visible object knowledge, provisional removals,
retraction state, synchronization labels, staged region bounds and time-policy
state. A successful save commits the checkpoint; a failed save does not replace
a previously committed checkpoint with the same label. Federate application
state remains the federate's responsibility.

Restore preserves the authenticated stream, applies the restored identity and
local state before `federationRestored`, and discards callbacks from the previous
callback epoch. Request-derived callbacks retain the epoch captured before their
RPC, so a delayed pre-restore status cannot appear after the restored callback.
Obsolete queued callbacks are compacted at the restore boundary while preserving
save-terminal bookkeeping on the evoke thread. Ordinary service calls are blocked
from restore-begun admission until the successful or failed terminal callback is
processed. Restore progress and completion services remain usable during restore.
Restore attempts use atomic identity tokens, so an older failed attempt cannot
clear a later admitted attempt's service gate. Federation-list reports are
connection-scoped and survive join and restore boundaries independently of
federate callbacks.

## Wire Compatibility

`FederationNotSaved` and `FederationNotRestored` gain optional `int32 reason`
fields at tag 2. The Go gRPC adapter forwards the existing domain failure reason;
Java maps all six save and five restore reasons to the standard enums. Missing or
unknown reason values fail explicitly rather than producing an invented reason.

No RPC signature or existing field number changes. The descriptor tests remove
only the two new fields and their synthetic optional oneofs and reproduce the
previous complete descriptor hash. Older additive-projection baselines are
preserved. Existing clients can ignore the optional metadata; Java failure-reason
callbacks require the updated server.

## Remaining Work

- `associateRegionsForUpdates` is pending: the existing backend replaces bindings;
  the standard service requires additive association. It is not counted as mapped.
- Heterogeneous region sets in one subscription, unsubscription or update-request
  call need an atomic pair-preserving wire operation. Empty destructive forms and
  unsupported registration bindings are rejected before mutation.
- Region queries need caller-specific conveyed-region knowledge enforcement.
- Java local checkpoints are in memory. Restart or resign/rejoin restoration
  requires durable or authoritative reconstruction of local SDK state.
- Ownership cancellation error metadata and the backend's extra confirmation on
  divest-if-wanted require a separate normative correction. RTI-owned attribute
  results have no defined wire representation yet.
- Remaining standard services include transportation/order changes, advisory
  switches, update-rate queries, automatic resign configuration and normalization.
- End-to-end Integer64 time, immediate callbacks, Linux execution and cross-binding
  stateful scenarios remain separate acceptance work.

The results establish the tested Java service paths. They do not close the entire
Java mapping or the whole-RTI IEEE 1516-2010 conformance assessment.
