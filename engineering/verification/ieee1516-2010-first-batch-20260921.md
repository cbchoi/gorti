# IEEE 1516-2010: First Conformance Implementation Batch

Date: 2026-09-21

This record continues the
[conformance execution plan](../design/ieee1516-2010-conformance-execution-plan.md).
It implements bounded portions of W1, W3 and W4, with Python as the primary
live-client verification path. It does not mark those entire milestones, the
normative inventory or full IEEE 1516-2010 conformance complete.

## Source And Method

Requirements were taken from the active 2010 text of the three supplied redline
documents. The [source review](ieee1516-2010-normative-review-20260921.md) records
their identities and hashes. Deleted text was excluded; the relevant pages were
visually reviewed. Licensed source files and execution logs remain outside Git.

Six parallel work streams covered time/source review, FOM admission, DDM,
ownership, Python integration and Linux verification. Implementation followed
plan, do, review and reflect: first reproduce a bounded behavioral defect, apply
the correction, review failure/restore/locking paths, and rerun the affected and
broader tests. Failed intermediate runs were retained rather than discarded.
An independent work stream is not an independent standards certification body.

## Implemented Behavior

### Time Management

IEEE 1516.1-2010 8.1.3-8.1.4, 8.1.7 and 8.19-8.20, supplied PDF
pp. 184, 189 and 213-214:

- Reject lookahead modification while an advance is genuinely pending. Tests
  use a second regulator to hold the request pending, rather than assuming a
  single-federate request waits.
- Keep requested and actual lookahead separate. An increase is immediate; a
  decrease takes effect as granted logical time advances. A same-time grant does
  not reduce it. Query operations return the actual interval.
- Use projected actual lookahead at the pending request horizon for outgoing
  validation and the existing grant evaluator's regulating snapshot.
- Reject a representable timestamp below a positive-lookahead floor. The former
  fixed `1e-9` tolerance no longer admits such timestamps.
- Commit or roll back the actual lookahead together with the grant state when
  callback admission fails, for reserved and legacy outboxes.
- Retain the reduction's original interval/time. Repeated sub-ULP advances must
  not lose the accumulated reduction; the test compares four small advances with
  the equivalent single advance, including an intervening restore.
- Refresh MOM's cached time state after successful grants, outside evaluator
  and state locks. State-change notifications report the real logical time
  instead of resetting it to zero. Reentrant observers and partial-success
  grant batches are covered.

Time snapshots use version 2 when a reduction is pending, including its target
and origin. The reader still accepts version 1, and ordinary state still writes
version 1. Restore graph validation and federate rebinding accept the new version.
Invalid targets/origins are rejected before mutation. Older readers are expected
to reject version 2 rather than silently lose this state. Scheduled-save tests
cover positive, zero and decreasing-to-zero lookahead before and after restore.

Primary production paths: `rti/internal/hla/time/` and
`rti/internal/adapters/savebundle/time.go`.

### FOM Admission

IEEE 1516.1-2010 4.1.4-4.1.4.1, supplied PDF pp. 47-49:

- Existing complete object/interaction classes require identical regular member
  sets. Adding attributes or parameters to those classes is rejected atomically.
- Legal new classes/subclasses and scaffolding completed in the same module
  combination remain accepted. Declaration order does not change existing handles.
- Permitted descriptive differences do not invalidate an otherwise compatible
  merge; the retained description is deterministic. Operational conflicts still
  reject the candidate.
- Integration fixtures now contribute legal new subclasses instead of relying
  on forbidden existing-class growth. Lease, stale-CAS, handle stability,
  current-FDD visibility and save/restore assertions remain in place.

Primary production paths: `rti/pkg/fom/parser/class_merge.go` and `parser.go`.
Tests also exercise the composition layer, current-FDD MOM reporting and the
existing Python live-join scenario. A new live admission test checks rejected
joins directly through gRPC and accepted joins through the Python SDK; the
SDK's commit-unknown classification for failed joins remains a separate W6 item.

### Data Distribution Management

IEEE 1516.1-2010 9.1.3-9.1.4 and 9.10-9.11:

- Region dimensions may be a proper subset of the available dimensions.
- Explicit regions overlap when they share at least one dimension and all shared
  dimensions overlap. A dimension omitted on one side adds no constraint.
- Interaction regional subscriptions accumulate. Active/passive state belongs
  to each subscriber/class/region combination; changing one region preserves the
  others. Targeted removal preserves ordinary subscriptions and remaining regions.
- Empty interaction-region subscribe/unsubscribe collections have no effect.
- Snapshots retain disjoint per-region option groups in deterministic order.
  Restore accepts those groups and proper subsets, while rejecting duplicate
  combinations, foreign or missing regions, invalid bounds and broken interest
  state. Failure preparation leaves live state unchanged.

Primary production paths: `rti/internal/hla/ddm/` and
`rti/internal/adapters/savebundle/restore_graph_declaration.go`.

### Ownership

IEEE 1516.1-2010 7.2.5(a-c), 7.3.5(b-d) and 7.6.5(c-e):

- Unconditional, negotiated and confirmed divestiture validate the caller's
  object knowledge, defined attributes and ownership before mutation.
- Divestiture does not incorrectly require acquisition publication.
- Production composition supplies a narrow object-validation port. The object
  is pinned before ownership mutation and released before journal, observer and
  callback calls, preserving the existing object-to-ownership lock order.
- Mixed valid/invalid attribute collections fail without partial mutation or
  transfer callbacks. Real gRPC and Python scenarios retain successful controls.

Primary production paths: `rti/internal/hla/ownership/manager.go`,
`divest_validation.go`, and the ownership composition in
`rti/internal/application/server/run.go`.

## Review And Remaining Work

Review caught and corrected two issues in the initial time patch: repeated tiny
reductions lost precision, and MOM's scalar lookahead remained stale after a
grant. Further review identified an existing outgoing-message admission race:
timestamp validation releases its locks before delivery admission, so a
concurrent advance or lookahead change can invalidate the earlier check.
A coherent snapshot alone does not resolve that race. Its next test must pause
between validation and admission, advance a receiver, and verify that stale
timestamp admission cannot succeed. A race-detector pass is not evidence that
this semantic race is closed.

| Milestone | Remaining acceptance work |
| --- | --- |
| W0 | Complete the clause-level mandatory/conditional inventory and independent review; the current bounded rows are not a conformance denominator |
| W1 | Atomic send/advance admission, zero-lookahead strictness and grant history, idle RO eligibility, pending-horizon GALT and all advance-mode interactions |
| W2 | End-to-end exact integer64 and standardized float64 time representations, arithmetic, protocol and persistence |
| W3 | Standard create inputs/default MIM, permitted MIM extensions, complete XML admission and federation-lifetime/last-member cleanup |
| W4 | Late regional discovery, empty object-region unsubscribe semantics, zero-width overlap, remaining ownership states and confirmation-specific exception distinctions |
| W5-W6 | Callback-invocation accounting, remaining MOM/service contracts and complete Python argument/error/callback behavior |
| W7-W9 | A complete applicable standard language mapping, full internal evidence and the separate external assessment |

The full-2010 readiness check still rejects the claim: normative coverage and
independent evidence remain incomplete. The evidence manifest keeps
`coverage_complete: false`; no certification or full-conformance percentage is
reported. No performance comparison was rerun in this semantic correction batch.

The next implementation priority is W1's atomic outgoing admission and
zero-lookahead state machine, with separate W3/W4 work proceeding only in
non-overlapping packages. Preserve the new restore and Python cases while those
changes are integrated.
